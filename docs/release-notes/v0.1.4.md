## Breaking change — Python timestamp atoms are now naive

q timestamp atoms returned by the Python binding are now naive `datetime` values
with `tzinfo is None`. Version 0.1.3 returned UTC-aware values.

A q timestamp carries no timezone, and Arrow `timestamp[ns]` columns were already
naive. In 0.1.3 the same q value therefore compared unequal depending on whether
it was read as an atom or out of a column, and a value read from a column could
not be passed back as a query argument at all. Both now work.

**Migration.** If you need an aware value, attach the zone yourself:

```python
ts = conn.sync("first exec time from trade")  # 0.1.4: naive datetime
ts = ts.replace(tzinfo=timezone.utc)  # only if the data really is UTC
```

Do not assume UTC unless your q process guarantees it. A process that stores
`.z.P` holds local wall-clock times, and 0.1.3 labelled those UTC — so an
`astimezone()` call on a 0.1.3 value could shift it silently.

**Argument handling.** Query arguments now accept both shapes. A naive `datetime`
keeps its wall clock. An aware one is normalized through its UTC offset, covering
fixed offsets and `zoneinfo` zones including DST transitions. A `tzinfo` whose
`utcoffset()` returns `None` counts as naive, matching Python's own definition of
awareness.

**Precision.** Sub-microsecond digits that `pandas.Timestamp` keeps in
`.nanosecond` are preserved when such a scalar is passed as an argument, so a
value read from a `timestamp[ns]` column round-trips exactly. Whole Series and
DataFrame round-trips remain nanosecond-exact on every backend.

## Dependencies

Patched two advisories that were active in the compiled native graph:
`crossbeam-epoch` 0.9.20 (RUSTSEC-2026-0204) and `memmap2` 0.9.11
(RUSTSEC-2026-0186). Dropped the unused Polars `serde` feature, which removes the
unmaintained `bincode` (RUSTSEC-2025-0141) from every shipped binary. Bumped
`pyo3` to 0.29.2 and raised the `napi` floor to 3.12.2.

Raised the `apache-arrow` floor to `^21.2.0`: Arrow only gained cross-copy
`Symbol.hasInstance` identity for `Table` and `Vector` in 21.2, so earlier 21.x
releases could fail `instanceof` against values this package returns.
